# khod-ghofteha — agent rules

Persian (RTL), light-theme-only blog for the Telegram channel
[@said_to_who_reads](https://t.me/said_to_who_reads) («خود گفته ها»).
Next.js 16 + Fumadocs MDX + Tailwind v4, static export → GitHub Pages.
Package manager: **bun**. Scripts are Python 3 stdlib (no pip installs).

## Hard content rules (never break)

1. **Post text is verbatim.** Never rewrite, fix typos, translate, summarize,
   reorder, or "improve" anything a channel message says. Not even spacing,
   punctuation or emoji.
2. **Never hand-edit `content/blog/*.md` or `content/blog/photos/`.** They are
   generated by `scripts/import-telegram.py` and are overwritten on every import.
3. Allowed additions only:
   - **Tags** → `content/blog-tags.json` (`{"<message id>": ["tag", ...]}`),
     merged with the message's own #hashtags on import. Reuse existing tag
     names (see list on the home page / `grep -h '^tags' content/blog/*.md | sort | uniq -c`).
   - **Layout/presentation** → `src/` (components, CSS). Layout may *add*
     chrome around a post (meta, links, notices) but must not alter its text.
4. Title = the message's first line (first non-link line). If that line is
   longer than 100 chars it is a paragraph: title = clipped first line + `…`
   and the full text stays in the body. Done by the importer, don't override.
5. Only the channel's **own text messages** are imported. Forwarded messages,
   polls and media-only messages are skipped on purpose.
6. After any import or layout change touching posts, `bun run check:posts`
   must report `N/N posts verbatim`.

Full step-by-step flow: `.agents/skills/telegram-post-import/SKILL.md`.

## Commands

```bash
bun install
bun run dev                     # http://localhost:3000
bun run import:telegram "<path>/ChatExport_YYYY-MM-DD"   # regenerate posts
bun run types:check
bun run build                   # static export → out/
bun run check:posts "<path>/ChatExport_YYYY-MM-DD"       # verbatim check (after build)
```

Preview the GitHub Pages build locally (served under `/khod-ghofteha/`):

```bash
GITHUB_PAGES=true GITHUB_REPOSITORY=saeed0920/khod-ghofteha bun run build
mkdir -p /tmp/kg && ln -sfn "$PWD/out" /tmp/kg/khod-ghofteha && (cd /tmp/kg && python3 -m http.server 3124)
# open http://localhost:3124/khod-ghofteha/
```

## Deploy

Push to `main` → `.github/workflows/deploy.yml` builds with
`GITHUB_PAGES=true` (sets `basePath=/<repo>`) and publishes `out/` to
GitHub Pages: https://saeed0920.github.io/khod-ghofteha/ .
PRs run `.github/workflows/check.yml` (types + build).
Repo Settings → Pages → Source must be **GitHub Actions**.

## Code rules

- RTL first: use logical utilities (`ps/pe/ms/me/start/end`), never assume left/right.
- Light theme only: `RootProvider theme={{ enabled: false }}`; don't add `dark:` styles.
- Colors come from tokens in `global.css` (`bg-page`, `text-ink`, `bg-accent`, …), not new hex values.
- Don't put `·` next to Persian digits (reads as ۰) — use `<Dot />`.
- Static export: no server-only features (route handlers must be `force-static`,
  no middleware, no `next/image` optimization). Internal links via `next/link`
  so `basePath` is applied; raw `fetch` must prefix `process.env.NEXT_PUBLIC_BASE_PATH`.
- Search normalizes Arabic ي/ك → ی/ک and ZWNJ; keep that when touching search.
